## 想自己重新编译

在 PowerShell 中执行下面的完整命令。无需先切换目录，也不需要先打开 Visual Studio：

```powershell
$root = 'D:/Tools/renderdoc'
$msbuild = 'C:/Program Files/Microsoft Visual Studio/2022/Professional/MSBuild/Current/Bin/MSBuild.exe'
New-Item -ItemType Directory -Path "$root/build-local" -Force | Out-Null
$oldCL = $env:CL
try {
    $env:CL = '/MP1'
    & $msbuild "$root/renderdoc.sln" '/m:1' '/nr:false' '/p:Configuration=Release' '/p:Platform=x64' '/p:PlatformToolset=v143' '/p:VisualStudioVersion=17.0' '/p:VCToolsVersion=14.38.33130' '/p:WindowsTargetPlatformVersion=10.0.22621.0' '/p:CL_MPCount=1' '/v:minimal' '/fl' "/flp:logfile=$root/build-local/build-x64-release.log;verbosity=normal;encoding=UTF-8"
    $buildExitCode = $LASTEXITCODE
    Set-Content "$root/build-local/build-x64-release.exitcode" $buildExitCode
    if ($buildExitCode -ne 0) {
        throw "编译失败，退出码 $buildExitCode，请查看构建日志。"
    }
} finally {
    $env:CL = $oldCL
}
```

这是增量构建：没有变化的文件通常不用重新编。首次编译会慢一些。低并发是为了降低内存和 CPU 压力，并不代表 RenderDoc 只能单线程编译。

如果换电脑，MSBuild 路径、MSVC 版本和 SDK 版本需要按新电脑已安装的环境调整。缺少 C++ 工具链时，在 Visual Studio Installer 中安装“使用 C++ 的桌面开发”和 Windows SDK，再重新编译。

源码开发调试可使用 `Development` 配置；正常使用或评估性能优先 `Release`。本次只编译 x64，没有编译 Win32、Android 或安装包。

## 编译后用哪个文件？

| 文件或目录 | 作用 |
| --- | --- |
| `D:/Tools/renderdoc/x64/Release/qrenderdoc.exe` | 带图形界面的主程序，日常使用打开它 |
| `D:/Tools/renderdoc/x64/Release/renderdoccmd.exe` | 命令行工具，可先运行 `--help` 查看功能 |
| `D:/Tools/renderdoc/x64/Release/renderdoc.dll` | 捕获与回放的核心库，不能随便拿别的版本替换 |
| `D:/Tools/renderdoc/x64/Release/obj` | 中间文件，不是要启动的程序 |

这是构建输出目录，不是安装包。正常使用请保留配套 DLL、插件和数据文件；不必把 `obj` 当作运行依赖，但也不需要为了启动程序去清理它。

## 出错时看哪里？

完整构建日志：[build-x64-release.log](D:/Tools/renderdoc/build-local/build-x64-release.log)。

构建退出码：[build-x64-release.exitcode](D:/Tools/renderdoc/build-local/build-x64-release.exitcode)。`0` 表示编译命令成功退出；其他值需要查看日志里的错误。

查看日志末尾的错误汇总，优先修复第一个真正的错误。警告不等于失败，而某些工程会把警告当成错误；最终以构建结果和退出码为准。
